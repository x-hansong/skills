# Changelog

All notable changes to this repository. Versions follow [Semantic Versioning](https://semver.org) and are tagged `vX.Y.Z`.

## Unreleased

### Changed

- Routed orchestrators (`paseo-routed`, `native-routed-*`): the rules that did not depend on the host moved out of each `SKILL.md` into shared files under `src/shared/routed/`: `brief.md`, `acceptance.md`, `report.md` and `reviewer-use.md`, rendered into all three skills. `paseo-routed/SKILL.md` went from 3777 to 1577 words. Before this, the Paseo skill was edited by hand while the native skills were rendered, so the last five Paseo rule changes (verdict block, pre-flight through a verifier, stop file, U+FFFD check, `progress.md` helper) never reached the native skills. Native users now get them.
- Routed orchestrators: a new `reviewer-use.md` lists every case where the reviewer runs (an implementation commit about to be delivered, a pre-flight of a brief, a changed write skill, a second failure, a user request or a disputed conclusion) and states that exploration, research and diagnosis reports are accepted from the verdict block and their evidence. Before, the step 5 text said research is not auto-reviewed while the Acceptance section sent every check to a reviewer-profile verifier, and an orchestrator followed the second.
- `scripts/check.sh` caps each routed `SKILL.md` at 1700 words and checks that each points at the shared files, so a new rule has to go into `src/shared/routed/`.

- `paseo-routed`: judgment acceptance, from a judge-repair run where two prompt rewordings failed. A judgment that cites nothing (an absent verdict) is checked against the judge's full input. Each wrong judgment is attributed to the judge or to the item's own wording (a prohibition or "not required" clause listed as a required element), and a flawed item is fixed instead of rewording the judge prompt.

- `paseo-routed`: two gaps seen in an operations run where four workers in a row each stopped on one environment blocker. The brief pre-flight gains a Tools check: the verifier runs the version and `--help` of every CLI subcommand the brief prescribes, including commands a user pasted from their own machine, and reports whether each subcommand and flag is accepted. An agent that stopped on a named stop condition resumes in place, with one message saying what changed, when the scope is unchanged and the blocker was cleared outside it; a changed scope or new directive still goes to a fresh agent.

- `paseo-routed`: `paseo-access.md` picks the workspace by the kind of work. Exploration, research, review, diagnosis and tasks with no repository run in the orchestrator's current workspace (`workspaceId` omitted); only implementation in a repository gets a `worktree` workspace. A `local` workspace on the notes directory is ruled out, since Paseo registers any unowned path as a new project.

- `paseo-routed`: four gaps seen in a long orchestration run. The brief pre-flight (contract and data assumptions) goes to a read-only verifier on the reviewer profile; the Roles table now also bars the orchestrator from opening source to check a brief, which the pre-flight text used to require. Long drivers stop through a stop file checked between cases, and the brief says why freezing or killing the process voids the case in flight. The Report names agents by the title Paseo shows and explains an internal term on first use. Before reporting, conclusions given to the user move into a document the project's entry file routes to, not only the notes.

- `paseo-routed`: three gaps seen in two long orchestration runs. A baseline is re-fetched before a build, install, upgrade, publish or push, and integrated first when the remote moved. The stop-condition table gains a row for a long job already doomed (failed upload before verification, stalled download) or running on a stale baseline: stop waiting, report the evidence, and do not kill an external-service run without the user's say; a killed run's exit file can read 0. Worker reports open with a verdict block of at most 15 lines so the orchestrator reads that and drills down only where disputed. Reports state the scope a conclusion covers, and text is checked for U+FFFD with a pattern that works under a UTF-8 locale.

- Routed orchestrators (`paseo-routed`, `native-routed-*`): when the deliverable is a set of judgments (scores, verdicts, labels), a summary count is inconclusive; the orchestrator reads the reason and cited material for every item whose judgment changed or disagrees with a reference label, and compares against a labelled reference set when the project keeps one.

- `paseo-routed`: acceptance no longer has the orchestrator verify by reading source. It checks that the deliverable exists, reruns the commands the brief names, reads the files the agent produced and diffs only through `--stat` (in full when one screen); every other check goes to a read-only verifier on the reviewer profile, given the claims, commands and artifact paths. The stop-condition table gains a row for lint, format and type failures (fix in place and rerun), and a docs-only commit whose diff fits one screen may be delivered without a new review verdict when the orchestrator read it. `paseo-access.md` states that `create_agent` needs `provider/model`, that agent tools take only the full agent id, and which `list_agents` filters to use.

- Routed orchestrators (`paseo-routed`, `native-routed-*`): the brief step starts with `git fetch`, so a baseline SHA read from `origin/<branch>` is the remote's current tip and not a stale local ref.

- Routed orchestrators (`paseo-routed`, `native-routed-*`): exploration and research briefs deliver facts only, with no recommended design or plan section, so the orchestrator writes the design itself; before a brief is sent, every literal value in the decided design cites its validating type or rule, and every assumption about input data is run as a query over the real data.

- `paseo-routed`: a new Notes section gathers what `progress.md` holds (decisions tagged by decision-maker, live agent and workspace IDs, reviewed SHA per repository, open gates); finished resources move to `log.md`. Delivery requires a reviewer verdict on the final HEAD, including fixes and merge-conflict resolutions. Briefs get a pre-flight with two checks: contract and integration (merge when acceptance checks commit ancestry). Cleanup archives only `worktree` workspaces this task created; `local` workspaces keep their directory. Counts treat a re-scored copy as the same run and a retry as a new run.

- Shared routed test discipline: reuse a result for the same SHA and command, preserve check exit codes, confirm timeout units.

- Routed review method: two new smells, Swallowed Failure (catches, fallbacks, defaults or retries that hide errors) and Compatibility Shim (old paths nobody needs); findings of these and of Speculative Generality / Middle Man name the code to remove and why; a changed shared function is reviewed against all its callers. Design principles: Boundary Discipline lists the guards to keep and how fallbacks skip it; Subtract Before You Add rules out compatibility for callers that don't exist.

- Routed orchestrators: `scope.md` opens with a keyword line; done-conditions name the surface the user checks; `progress.md` stays under 40 lines, is rewritten only by the orchestrator, and lists deferred project gates; agents append to `log.md`. Worktree cleanup copies outputs that a main-checkout tool reads back to the main checkout instead of only to the notes.

### Added

- `paseo-routed` ships `scripts/set-progress.sh`, which appends to or replaces one section of `progress.md` (a heading section or a label such as `Current step`), reads lines from standard input when none are given, and refuses a result over 40 lines. Its tests run in `scripts/check.sh`.

- `paseo-routed` ships `scripts/init-notes.sh`, which creates the notes directory with `scope.md`, `progress.md` (live resources, reviewed SHA, open gates), `log.md` and the test, review and principles copies, and refuses to overwrite existing notes.

- Routed skills ship `scripts/wait-job.sh` for bounded waits on a PID or completion command, with log tails and a retryable exit code while the job is still running.

- Paseo Routed group: `paseo-routed`, `implement-routed`, `implement-spec-routed`, `setup-paseo-routed`, `paseo-routed-guide`.
- Rosters in `~/.paseo-routed/config.yaml` map the `worker` and `reviewer` roles to Paseo profiles; switch per run with `--roster <name>`.
- `paseo-watch`: a Paseo heartbeat patrols top-level orchestrator agents and reports only what changed; every pending decision comes with its background rebuilt (task, path so far, blocker, options, what happens without an answer) and a stable `D<n>` id; answers and standing rules are relayed with explicit authorised / not-authorised scope; state persists in `~/.paseo-routed/.watch/state.json`.
- `setup-paseo-routed` detects existing setup, plans only the missing pieces, writes after confirmation and re-checks; profiles are written through a script that preserves every other profile.
- Native Routed group: the same worker / reviewer split without Paseo, on each host's own subagents. Six skills per host, suffixed `-cc` (Claude Code Agent tool) and `-codex` (Codex `spawn_agent`): `native-routed-*`, `native-implement-routed-*`, `native-implement-spec-routed-*`, `native-watch-*`, `native-routed-guide-*`, `native-routed-setup-*`.
- Native Routed models live in `~/.native-routed/config.yaml`, one section per host: the reviewer and a two-member committee run on stronger models than the worker. Codex has no built-in defaults; its setup suggests values from the models `spawn_agent` offers.
- `paseo-watch` and `native-watch-*` track idle time: an orchestrator idle past `stallMinutes` (default 30) with unfinished work is reported as stalled even when nothing else changed, and a child's progress is no longer reported as the parent's; a pending decision whose agent is about to lose its prompt cache (`cacheTtlMinutes`, default 60, provider-dependent, `null` to turn off) gets a warning, and is marked `cold` after.
- `native-watch-*` finds runs through `session.json` in `~/.native-routed/notes/<topic>/`; Claude Code patrols with `CronCreate` and relays with `SendMessage`, Codex patrols with a heartbeat automation where available (on demand otherwise) and relays with `codex queue`.

### Changed

- Routed acceptance (`paseo-routed`, `native-routed-*`): every count the orchestrator reports comes from a script over the deliverables, not a hand sum of agent reports. Test discipline: when the pinned static-check tool is missing, workers run it through an isolated runner (`uvx ruff ...` for Python) instead of skipping.
- Routed briefs name an absolute worktree path for every writable repository, including the orchestrator's workspace, and keep main checkouts read-only. Workers start long jobs with logs and call the bundled wait script repeatedly in the same turn until the job finishes.
- Routed test discipline (`paseo-routed`, `native-routed-*`): workers run the affected tests and the changed files' static checks before each commit, and no longer run the full suite at the end or wait on CI unless the brief asks; the report says the full suite was not run.
- `setup-paseo-routed` and `native-routed-setup-cc` check the Explore subagent's model. The built-in `Explore` and `Plan` are `model: inherit`, so they skip `CLAUDE_CODE_SUBAGENT_MODEL` and run on the session model. When that variable is set and no override exists, setup offers a read-only `Explore.md` override with the variable's model, backs up any existing file, and can prove the result with one `claude -p` run.
- Routed skills (`paseo-routed`, `native-routed-*`): every brief states a positive write scope (where the agent may write, what done leaves behind); agents reply done only when the deliverable exists, after their own subagents and background jobs finish; the orchestrator checks the deliverable on each finish. `paseo-routed`'s `paseo-access` notes that MCP agent tools take full agent ids.
- Routed review: a claim that a path is connected (dry run, precheck, adapter or contract test) needs a check that hands the real output to the real downstream consumer; a check of the change's own format alone is a Spec finding. Applies to `paseo-routed` and `native-routed-*`.
- `paseo-routed`: follow-up messages use `paseo send --no-wait`, since `send` otherwise blocks until the agent's turn ends; long messages go through `--prompt-file`.
- Routed skills (`paseo-routed`, `native-routed-*`): before removing a worktree, copy the ignored files this task produced (run outputs, baselines, private data) to the main checkout or the notes directory.
- `paseo-routed`, `native-routed`: briefs read every SHA and branch fact from an explicit ref such as `origin/<branch>`, never `HEAD`; agents watch long jobs to a terminal state within the same turn, since no background monitor wakes them after it ends.
- README has a usage section: a command-name table across the Paseo and native sets, a small-work path (`paseo-routed`, `implement-routed`) and a large-work path (`grill-with-docs` → `to-spec` → `to-tickets` → `implement-spec-routed` → `retro`), each with examples. It lists optional companions from mattpocock/skills (`grilling`, `grill-with-docs`, `to-spec`, `to-tickets`, `retro`) with their dependencies `domain-modeling`, `setup-matt-pocock-skills` and `writing-for-agents`. The getting-started guide no longer says setup checks mattpocock/skills dependencies.
- Review findings need proof. A P0–P2 behaviour or Spec finding carries the command that shows it, the output it printed and the output required; the orchestrator reruns it before handing it to a fixer, and the fix is done when the same commands print the required output. Findings without a run are listed as Unproven for the user. Applies to `paseo-routed` and `native-routed-*`.
- Acceptance checks get one verdict each: verified, not verified or inconclusive; inconclusive is not a pass. The routed skills open by restating the goal, and the final report labels each claim as measured, inferred or a guess.
- `native-routed-*` models: a `budget` (`small`, `medium`, `large`, `unlimited`) sets the effort of every role without its own; roles take `inherit` or `{ model, effort }`; `committee` takes two or more entries, one member each; `--budget` overrides for one run. A model that fails to start mid-run falls back in a fixed order, and the fallback is recorded and reported.
- The `-cc` and `-codex` twins, and the review and test references shared with `paseo-routed`, are rendered from `src/` by `scripts/render.sh`; `scripts/check.sh` fails when the rendered files drift, when a twin is missing, or when a routed skill loses a section the other skills rely on.
- README lists which skills to install together.
- Routed orchestration rules from pstack's poteto-mode, in `paseo-routed` and `native-routed-*`: a fresh agent that takes over earlier work gets a consolidated brief (original brief, later directives, prior report and branch), and a mid-run scope change narrows the running agent and hands the new scope to a fresh one; several similar units run the first one end to end before the rest; failed agents are retried by cause, and a repeated failure goes to the committee with the premise the attempts share, to be tested first; `progress.md` in the notes is the resume point, and resume trusts the notes but re-verifies claims the next step relies on; forks that a run could settle go to a worker instead of the user; work past the brief is sent back, a review verdict covers one head SHA, "might help" and refuted-hypothesis changes are reverted, and the report accounts for every agent started.
- Implementation briefs in `paseo-routed` and `native-routed-*` carry the decided design: file paths, the data shape and its organizing structure, trade-offs already made and boundary rules. The worker follows it and reports back before changing it.
- `paseo-routed` and `native-routed-*` ship a shared `principles.md` adapted from pstack: Model the Domain, Boundary Discipline, Subtract Before You Add, Minimize Reader Load, Make Operations Idempotent, Explain the Number. The orchestrator reads it before writing the decided design, the reviewer applies it as a P3 judgement-call baseline next to the smell list, and the report names each principle that changed a decision.

### Fixed

- `set-progress.sh` lists the sections that exist when the name is not found, and says a label is given without its colon. `init-notes.sh` writes labels such as `Intent:` into `progress.md`, so an agent copying one of them was refused with no hint of the valid names.
- Bounded routed waits stop completion-check process groups on timeout and clean up descendants after a check exits, so captured output closes without stopping an observed PID.

- Private-value checks exclude the `.git` pointer file in worktrees, as well as the `.git` directory, so repository metadata is not mistaken for a private value in project files.

- The routed skills no longer depend on other skill sets, only on Paseo for the Paseo group. `implement`, `implement-spec` and `tdd` are manual-only skills a model can't load, so the implement skills stopped or worked around the block. Their flow now lives in the skills themselves, and `paseo-routed` and `native-routed-*` carry `references/tests.md` (test discipline) and `references/review.md` (two-axis review), copied into the run's notes so subagents read them by path. Adapted from [mattpocock/skills](https://github.com/mattpocock/skills) (MIT). Setup no longer checks or installs `implement`, `implement-spec`, `tdd` or `code-review`, and `scripts/check.sh` rejects skills that load one of them.
- `paseo-watch` and `native-watch-*` decide stall state afresh on every tick, so a stalled orchestrator stays listed until it moves instead of dropping out after the first report; facts carry their own time, and a stale one is no longer shown as progress. `paseo-watch` also reports a parent that missed its child's wake-up right away.
- A stalled orchestrator whose work another one took over is raised once as a decision (wake it or stop watching it) instead of being reported, or skipped, forever.
- Probes: on user confirmation the watch reads a background job's own state each tick (an import, a deployment, a monitor's output) and alerts when it stops, since an agent idling while it waits says nothing about the job.
- Watch reports are written entirely in the user's language, section headings included.
- Watch reports use one clock: every time is shown in the user's local zone, named once in the patrol title. Times read from Paseo tools, transcripts, rollouts, checkpoints and logs are converted before printing instead of pasted as raw `Z` values; a quoted source value carries its local equivalent, and a source with no known zone is reported by its age.
- A newly seen orchestrator gets its own line in the next report instead of blending into progress. Finished, one-off or watcher sessions are suggested for ignoring in one line, at most once each until they move again; nothing is ignored without the user's answer. `native-watch-*` says at `start` that plain sessions are watched only once pinned.
