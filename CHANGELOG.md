# Changelog

All notable changes to this repository. Versions follow [Semantic Versioning](https://semver.org) and are tagged `vX.Y.Z`.

## Unreleased

### Added

- Paseo Routed group: `paseo-routed`, `implement-routed`, `implement-spec-routed`, `setup-paseo-routed`, `paseo-routed-guide`.
- Rosters in `~/.paseo-routed/config.yaml` map the `worker` and `reviewer` roles to Paseo profiles; switch per run with `--roster <name>`.
- `paseo-watch`: a Paseo heartbeat patrols top-level orchestrator agents and reports only what changed; every pending decision comes with its background rebuilt (task, path so far, blocker, options, what happens without an answer) and a stable `D<n>` id; answers and standing rules are relayed with explicit authorised / not-authorised scope; state persists in `~/.paseo-routed/.watch/state.json`.
- `setup-paseo-routed` detects existing setup, plans only the missing pieces, writes after confirmation and re-checks; profiles are written through a script that preserves every other profile.
- Native Routed group: the same worker / reviewer split without Paseo, on each host's own subagents. Six skills per host, suffixed `-cc` (Claude Code Agent tool) and `-codex` (Codex `spawn_agent`): `native-routed-*`, `native-implement-routed-*`, `native-implement-spec-routed-*`, `native-watch-*`, `native-routed-guide-*`, `native-routed-setup-*`.
- Native Routed models live in `~/.native-routed/config.yaml`, one section per host: the reviewer and a two-member committee run on stronger models than the worker. Codex has no built-in defaults; its setup suggests values from the models `spawn_agent` offers.
- `paseo-watch` and `native-watch-*` track idle time: an orchestrator idle past `stallMinutes` (default 30) with unfinished work is reported as stalled even when nothing else changed, and a child's progress is no longer reported as the parent's; a pending decision whose agent is about to lose its prompt cache (`cacheTtlMinutes`, default 60, provider-dependent, `null` to turn off) gets a warning, and is marked `cold` after.
- `native-watch-*` finds runs through `session.json` in `~/.native-routed/notes/<topic>/`; Claude Code patrols with `CronCreate` and relays with `SendMessage`, Codex patrols with a heartbeat automation where available (on demand otherwise) and relays with `codex queue`.

### Changed

- Routed review: a claim that a path is connected (dry run, precheck, adapter or contract test) needs a check that hands the real output to the real downstream consumer; a check of the change's own format alone is a Spec finding. Applies to `paseo-routed` and `native-routed-*`.
- `paseo-routed`: follow-up messages use `paseo send --no-wait`, since `send` otherwise blocks until the agent's turn ends; long messages go through `--prompt-file`.
- Routed skills (`paseo-routed`, `native-routed-*`): before removing a worktree, copy the ignored files this task produced (run outputs, baselines, private data) to the main checkout or the notes directory.
- `paseo-routed`, `native-routed`: briefs read every SHA and branch fact from an explicit ref such as `origin/<branch>`, never `HEAD`; agents watch long jobs to a terminal state within the same turn, since no background monitor wakes them after it ends.
- README has a usage section: a command-name table across the Paseo and native sets, a small-work path (`paseo-routed`, `implement-routed`) and a large-work path (`grill-with-docs` → `to-spec` → `to-tickets` → `implement-spec-routed` → `retro`), each with examples. It lists optional companions from mattpocock/skills (`grilling`, `grill-with-docs`, `to-spec`, `to-tickets`, `retro`) with their dependencies `domain-modeling`, `setup-matt-pocock-skills` and `writing-for-agents`. The getting-started guide no longer says setup checks mattpocock/skills dependencies.
- Review findings need proof. A P0–P2 behaviour or Spec finding carries the command that shows it, the output it printed and the output required; the orchestrator reruns it before handing it to a fixer, and the fix is done when the same commands print the required output. Findings without a run are listed as Unproven for the user. Applies to `paseo-routed` and `native-routed-*`.
- Acceptance checks get one verdict each: verified, not verified or inconclusive; inconclusive is not a pass. The routed skills open by restating the goal, and the final report labels each claim as measured, inferred or a guess.
- `native-routed-*` models: a `budget` (`small`, `medium`, `large`, `unlimited`) sets the effort of every role without its own; roles take `inherit` or `{ model, effort }`; `committee` takes two or more entries, one member each; `--budget` overrides for one run. A model that fails to start mid-run falls back in a fixed order, and the fallback is recorded and reported.
- The `-cc` and `-codex` twins, and the review and test references shared with `paseo-routed`, are rendered from `src/` by `scripts/render.sh`; `scripts/check.sh` fails when the rendered files drift, when a twin is missing, or when a routed skill loses a section the other skills rely on.
- README lists which skills to install together.
- Routed orchestration rules from pstack's poteto-mode, in `paseo-routed` and `native-routed-*`: a fresh agent that takes over earlier work gets a consolidated brief (original brief, later directives, prior report and branch), and a mid-run scope change narrows the running agent and hands the new scope to a fresh one; several similar units run the first one end to end before the rest; failed agents are retried by cause, and a repeated failure goes to the committee with the premise the attempts share, to be tested first; `progress.md` in the notes is the resume point, and resume trusts the notes but re-verifies claims the next step relies on; forks that a run could settle go to a worker instead of the user; work past the brief is sent back, a review verdict covers one head SHA, "might help" and refuted-hypothesis changes are reverted, and the report accounts for every agent started.
- Implementation briefs in `paseo-routed` and `native-routed-*` carry the decided design: file paths, the data shape and its organizing structure, trade-offs already made and boundary rules. The worker follows it and reports back before changing it.
- `paseo-routed` and `native-routed-*` ship a shared `principles.md` adapted from pstack: Model the Domain, Boundary Discipline, Subtract Before You Add, Minimize Reader Load, Make Operations Idempotent, Explain the Number. The orchestrator reads it before writing the decided design, the reviewer applies it as a P3 judgement-call baseline next to the smell list, and the report names each principle that changed a decision.

### Fixed

- The routed skills no longer depend on other skill sets, only on Paseo for the Paseo group. `implement`, `implement-spec` and `tdd` are manual-only skills a model can't load, so the implement skills stopped or worked around the block. Their flow now lives in the skills themselves, and `paseo-routed` and `native-routed-*` carry `references/tests.md` (test discipline) and `references/review.md` (two-axis review), copied into the run's notes so subagents read them by path. Adapted from [mattpocock/skills](https://github.com/mattpocock/skills) (MIT). Setup no longer checks or installs `implement`, `implement-spec`, `tdd` or `code-review`, and `scripts/check.sh` rejects skills that load one of them.
- `paseo-watch` and `native-watch-*` decide stall state afresh on every tick, so a stalled orchestrator stays listed until it moves instead of dropping out after the first report; facts carry their own time, and a stale one is no longer shown as progress. `paseo-watch` also reports a parent that missed its child's wake-up right away.
- A stalled orchestrator whose work another one took over is raised once as a decision (wake it or stop watching it) instead of being reported, or skipped, forever.
- Probes: on user confirmation the watch reads a background job's own state each tick (an import, a deployment, a monitor's output) and alerts when it stops, since an agent idling while it waits says nothing about the job.
- Watch reports are written entirely in the user's language, section headings included.
- Watch reports use one clock: every time is shown in the user's local zone, named once in the patrol title. Times read from Paseo tools, transcripts, rollouts, checkpoints and logs are converted before printing instead of pasted as raw `Z` values; a quoted source value carries its local equivalent, and a source with no known zone is reported by its age.
- A newly seen orchestrator gets its own line in the next report instead of blending into progress. Finished, one-off or watcher sessions are suggested for ignoring in one line, at most once each until they move again; nothing is ignored without the user's answer. `native-watch-*` says at `start` that plain sessions are watched only once pinned.
